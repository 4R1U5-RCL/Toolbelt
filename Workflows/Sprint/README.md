# Sprint — parallel multi-session workflow

Stand up a coordinated **fleet** of Claude Code sessions — one orchestrator, one reviewer, and N
workers — that work a single "sprint" in parallel and coordinate through two shared surfaces: a
**canonical `SPRINT.md` board** in a dedicated git worktree, and a **file mailbox** that carries
messages between sessions without depending on peer session-registration. The owner prompts twice
(plan, then per-worker handoff); those two prompts are the human gate around the autonomous loop.

Generated by the `/fleet` slash command. See **`docs/topology.html`** for the system diagram.

## Install

```sh
cp commands/fleet.md            ~/.claude/commands/
cp agents/fleet-triage.md       ~/.claude/agents/
mkdir -p ~/.claude/data/templates/fleet-kit
cp fleet-kit/*                  ~/.claude/data/templates/fleet-kit/
chmod +x ~/.claude/data/templates/fleet-kit/*.sh
```

> **One path to check:** `agents/fleet-triage.md` references the guard hook by absolute path
> (`/root/.claude/data/templates/fleet-kit/fleet-triage-guard.sh`). If your home isn't `/root`,
> set it to wherever `fleet-triage-guard.sh` actually lands.

## Quickstart

From the orchestration session, in your repo:

```
/fleet "<objective>" --sprint <slug> --workers 3 --resources "<contended rails>"
```

That creates the `sprint/<slug>` worktree + `SPRINT.md` + the scratch mailbox, then prints role
blocks for the orchestrator / reviewer / workers. Then:

1. Open one terminal per session, **each with a stable name**:
   `claude --name reviewer`, `--name worker-a`, `--name worker-b`… (see Known issues #3).
2. Paste each session its role block; **you** post each worker its task (the human gate).
3. The orchestrator triages inbound STATE via the `fleet-triage` subagent and folds results into
   `SPRINT.md`; run `fleet-doctor status <WT>` anytime for a board glance.

## How it works (one paragraph)

Messages travel as **one file per message** (atomic temp→rename, addressed by logical name
`orchestrator`/`reviewer`/`A`/`B`/`C`), so concurrent writers never collide and nothing is lost if
peer messaging can't resolve a session. The **orchestrator is the sole writer** of `SPRINT.md` —
workers only read it and report STATE — so appends never conflict and the board is always the single
source of truth. Every review packet carries a `sha256`; the reviewer cites it in its verdict and the
orchestrator only marks a task COMPLETE when that sha matches the task's current head packet.

## Known issues / caveats

1. **Advisory lock is age-based, not liveness-based.** A turn-based session can't hold a file
   descriptor across turns, so `fleet-mbox lock` uses an atomic-`mkdir` lockfile and `fleet-doctor`
   flags a holder older than `FLEET_LOCK_STALE_H` (default 6h) rather than proving it's dead.
   Clearing a stale lock (`fleet-mbox unlock <holder>`) is a human call.
2. **At-most-once delivery.** Recipients `peek → apply → ack`, which shrinks but doesn't eliminate the
   window where a crash could drop an unapplied message. This is intentional: the human is the
   failsafe — a lost STATE ping just shows as a stalled task the owner notices. A two-phase
   claim/ack protocol was deliberately **not** built (over-engineering at this scale).
3. **Reliable peer messaging needs stable names.** Claude Code's default `studio-XX` session names
   are derived and collide/churn, which makes `SendMessage`/`ListAgents` unreliable — the reason the
   mailbox exists. Launch sessions with `--name` (or `/rename`) to fix targeting; native messaging
   then works as a wake fast-path *on top of* the mailbox, which stays authoritative.
4. **Same-filesystem only.** The mailbox lives under `scratch/` and is shared by sessions on the same
   filesystem; a session inside a container and one on the host can't see each other's mailbox.
5. **Also deliberately skipped** as over-engineering for a small, single-host, short-lived, human-gated
   sprint (revisit only at larger scale / untrusted multi-tenant host): inbox signing/auth,
   SQLite/Maildir rewrite, retention policies, heartbeat watchdog, hand-rolled socket posting.
